# SOCKS + HTTP прокси с авторизацией в контейнере `socks/`

**Дата:** 2026-04-20
**Статус:** дизайн утверждён, к реализации

## Задача

Расширить существующий `socks/` контейнер, чтобы в режиме с авторизацией он мог одновременно обслуживать SOCKS5 и HTTP прокси с общими кредами. Оба протокола должны ходить через общий SSH `-D` туннель на удалённый сервер.

## Мотивация

3proxy уже собран в образ `socks/` и используется в auth-режиме. Он нативно поддерживает HTTP-прокси (`proxy` листенер) ровно так же, как SOCKS5 (`socks` листенер) — разница в конфиге одна строка. Выносить HTTP в отдельный контейнер значит дублировать тот же бинарь, тот же SSH-туннель и тот же ключ без выигрыша. Расширение существующего образа — минимальное изменение без влияния на размер и без новых сборочных зависимостей.

## Объём изменений

- `socks/entrypoint.sh` — добавить опциональный HTTP-листенер в конфиг 3proxy.
- `README.md` — обновить таблицу env, примеры RouterOS, раздел «Проверка».
- `CLAUDE.md` — обновить описание режимов `socks/`.

Dockerfile, сборочные шаги, ldd-зависимости, busybox-симлинки, размер образа — **не меняются**.

## Архитектура

Контейнер продолжает поддерживать три взаимоисключающих режима. Режим выбирается по наличию env-переменных на старте.

| Условие | Режим | Слушает |
|---|---|---|
| Нет `SOCKS_USER` или `SOCKS_PASS` | Чистый `ssh -D` (как сейчас) | SOCKS5 на `SOCKS_PORT`, без auth |
| `SOCKS_USER` + `SOCKS_PASS` заданы, `HTTP_PORT` не задан | 3proxy, SOCKS-only с auth (как сейчас) | SOCKS5 на `SOCKS_PORT` |
| `SOCKS_USER` + `SOCKS_PASS` + `HTTP_PORT` заданы | **Новый:** 3proxy, SOCKS + HTTP с auth | SOCKS5 на `SOCKS_PORT`, HTTP на `HTTP_PORT` |

Во всех auth-режимах 3proxy ходит наружу через локальный SSH `-D` туннель (`127.0.0.1:10800`) директивой `parent 1000 socks5`. SSH-туннель запускается в фоне в `while true; ssh -N ...; sleep 5` для авто-реконнекта — без изменений относительно текущего поведения.

## Переменные окружения

Добавляется одна переменная. Остальные — без изменений.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HTTP_PORT` | — (не задана → HTTP выключен) | Порт HTTP-прокси |

`SOCKS_USER` / `SOCKS_PASS` действуют на оба протокола (общие креды — AuthN в 3proxy глобален в рамках конфига).

Обратная совместимость: все существующие `container envs` на роутерах продолжают работать с идентичным поведением. `HTTP_PORT` не задан → HTTP выключен, режим совпадает с текущим SOCKS-only-auth.

## Конфиг 3proxy

В auth-режиме `/tmp/3proxy.cfg` генерируется так:

```
nscache 65536
timeouts 1 5 30 60 180 1800 15 60
log /dev/stderr
users ${SOCKS_USER}:CL:${SOCKS_PASS}
auth strong
allow ${SOCKS_USER}
parent 1000 socks5 127.0.0.1 ${SSH_TUNNEL_PORT}
socks -p${SOCKS_PORT} -i0.0.0.0
```

Если задана `HTTP_PORT` — скриптом дописывается одна строка:

```
proxy -p${HTTP_PORT} -i0.0.0.0
```

`auth strong` и `allow ${SOCKS_USER}` в 3proxy — глобальные директивы, действуют на все последующие листенеры, поэтому HTTP автоматически требует те же креды.

**Про `parent`:** директива применяется к последующим листенерам. Если при реализации выяснится, что sticky-поведение не срабатывает на второй листенер, `parent 1000 socks5 127.0.0.1 ${SSH_TUNNEL_PORT}` дублируется перед каждым листенером. Проверка — обязательный шаг валидации перед финализацией.

## Реализация

Изменение в `socks/entrypoint.sh` — в ветке auth-режима, после генерации базового конфига через heredoc:

```sh
if [ -n "${HTTP_PORT}" ]; then
  echo "proxy -p${HTTP_PORT} -i0.0.0.0" >> ${CFG}
fi
```

Сообщение в лог перед `exec 3proxy` обновить, чтобы отражало активные листенеры:

```sh
if [ -n "${HTTP_PORT}" ]; then
  echo "$(date) Starting 3proxy: SOCKS=${SOCKS_PORT}, HTTP=${HTTP_PORT}, auth=${SOCKS_USER}"
else
  echo "$(date) Starting 3proxy: SOCKS=${SOCKS_PORT}, auth=${SOCKS_USER}"
fi
```

Ветка без auth (`ssh -D`) не меняется.

## Валидация

CI в репозитории нет — проверка ручная на роутере:

1. **Регресс:** существующий деплой (без `HTTP_PORT`) после обновления образа ведёт себя идентично прежнему. `curl -x socks5://u:p@router:1080 https://ifconfig.me` возвращает IP удалённого сервера.
2. **Новый режим:** с `HTTP_PORT=3128`:
   - `curl -x socks5://u:p@router:1080 https://ifconfig.me` → IP удалённого сервера.
   - `curl -x http://u:p@router:3128 https://ifconfig.me` → IP удалённого сервера.
   - `curl -x http://router:3128 https://ifconfig.me` (без кредов) → `407 Proxy Authentication Required`.
3. **Режим без auth (опциональный регресс-тест):** убрать `SOCKS_USER`/`SOCKS_PASS`, `HTTP_PORT` неважно → контейнер запускает только `ssh -D` без 3proxy.
